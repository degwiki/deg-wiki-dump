# Дампы deg.wiki

Полные выгрузки содержимого [deg.wiki](https://deg.wiki) — чтобы сайт можно было прочитать
и восстановить независимо от сервера, на котором он работает.

**Скачать: [страница релизов](../../releases/latest).**

## Что в каждом релизе

| Файл | Что внутри |
|---|---|
| `deg-wiki-pages-ДАТА.xml.zst` | тексты всех страниц со всей историей правок, все пространства имён |
| `deg-wiki-images-ДАТА.tar.zst` | загруженные файлы: картинки, сканы |
| `SHA256SUMS-ДАТА.txt` | контрольные суммы |

## Как распаковать

```sh
zstd -d deg-wiki-pages-ДАТА.xml.zst
tar --zstd -xf deg-wiki-images-ДАТА.tar.zst
```

Формат zstd открывают: в Windows — 7-Zip, в macOS — `brew install zstd`, в Linux он обычно
уже установлен.

## Как поднять из этого свою копию вики

Понадобится установленная MediaWiki (та же версия или новее — дампы снимаются с 1.46):

```sh
php maintenance/run.php importDump --uploads < deg-wiki-pages-ДАТА.xml
tar --zstd -xf deg-wiki-images-ДАТА.tar.zst -C /путь/к/mediawiki/
php maintenance/run.php rebuildall
```

## Что сюда не входит

Учётные записи, пароли и служебные журналы — это не публичные данные. Миниатюры картинок
тоже не входят: MediaWiki создаёт их сама при первом показе.

## Как это работает

Раз в неделю [workflow](.github/workflows/mirror-dumps.yml) забирает свежий набор с
`https://deg.wiki/dumps/`, сверяет контрольные суммы, проверяет, что дамп страниц читается,
и публикует релизом. Если набор с такой датой уже опубликован, прогон ничего не делает.

Сам сервер вики про этот репозиторий ничего не знает и никаких ключей от GitHub не хранит.
